# Regras de negócio identificadas

As regras abaixo foram extraídas do código do snapshot `f50da548` e não são proposta de correção.

| ID | Regra | Implementação (trecho aproximado) | Consequência |
|---|---|---|---|
| REG-001 | Toda entidade operacional é limitada ao `grupo` do usuário; ausência de correspondência retorna 403/404. | `api/deps.py::require_*_grupo` | Não remover filtros tenant ao criar endpoints novos. **F4:** o admin também fica restrito ao próprio grupo; só o admin geral (`SUPER_ADMIN_EMAILS`) vê todos. Grupo desativado bloqueia o acesso dos usuários dele. |
| REG-002 | Usuário precisa estar ativo e com e-mail verificado; só existem os papéis `admin` e `operador` (o `leitura` foi convertido em operador pela revisão `0003`). O JWT carrega `ver` = `usuarios.token_version`; trocar ou redefinir a senha incrementa e derruba as sessões antigas. | `api/deps.py`, `core/security.py`, `services/contas_service.py` | JWT válido de usuário desativado, não verificado ou com versão antiga não autoriza. |
| REG-003 | Login é limitado por IP real + email (8 tentativas em 5 minutos). Atrás do proxy do Railway o IP vem do último endereço do `X-Forwarded-For` (`core/rede.py::ip_cliente`). Login leva o mesmo tempo com e-mail existente ou não. | `core/rate_limit.py`, `core/rede.py`, `routers/auth.py` | Limite é por processo, não distribuído. |
| REG-004 | Empresa usa CNPJ normalizado com 14 dígitos e é única no banco. | `empresas_service.py`, `models.Empresa` | CNPJ inválido/duplicado falha antes do commit. |
| REG-005 | Consulta elegível requer certificado ativo, empresa ativa/grupo compatível, `storage_key` não pendente, validade e senha salva. | `consultas_service.py::list_certificados_elegiveis` | Certificado sem segredo não entra no scheduler. |
| REG-006 | Não é criado novo processo para certificado com consulta ativa, salvo opção explícita de força. | `consultas_service.py::has_active_consulta_for_certificado` | Evita duplicidade lógica, mas corrida entre sessões ainda é possível. |
| REG-007 | `MonitoramentoConfig.grupo` é único; scheduler enfileira apenas grupos automáticos ativos e no horário. | `consultas_service.py`, `worker/scheduler.py` | Configuração de um grupo não afeta outro. |
| REG-008 | Cursor NSU é monotônico por `(empresa_id, certificado_id)`; lookback normal/deep depende da janela e opção. | `nsu_control_service.py` | Reprocessamento deve ser idempotente. |
| REG-009 | `Processo` passa por `pendente → executando → finalizado/erro/cancelado`; `Job` tem attempts e lock. | `processos_service.py`, `worker/jobs.py` | Cancelar `running` marca estado, mas não interrompe cliente legado. |
| REG-010 | Em `WORKER_DRY_RUN=true`, o job simulado atualiza estados sem chamar ADN. | `worker/jobs.py::processar_job_simulado` | Ambiente local não valida integração real. |
| REG-011 | Lock de processamento é único por empresa/certificado e tem expiração. | `locks_service.py`, `models.LockProcessamento` | Worker morto depende de expiração/recovery. |
| REG-012 | Chave `(empresa_id, nota.chave)` é a identidade idempotente da nota. | `models.Nota`, `legacy_ingestion_service::upsert_nota_by_chave` | Mesma NFS-e em empresas distintas é permitida. |
| REG-013 | Namespace XML é ignorado para localizar tags; datas/decimais recebem normalização tolerante. | `legacy_ingestion_service.py`, `nfse_xml_parser.py` | XML malformado/sem chave é rejeitado ou enviado a erro de ingestão. |
| REG-014 | `status_documento` vem só da estrutura do XML, nunca de palavras do texto (descrição, nome, motivo). Raiz `<NFSe>` é nota; raiz `<evento>` é evento. Nota: cStat 100, 101 (substituta), 102 (decisão judicial) e 103 (avulsa) → `autorizada`/"Autorizada"; 107 → `autorizada`/"MEI"; outro cStat → `cstat_N` visível. Evento, pelo código: e101101 e e105104 (deferido) → nota `cancelada`; e105102 → nota `substituida`; e101103 (solicitação), e105105 (indeferido) e manifestações (e203202, e203206) não mudam status; código desconhecido não muda status e gera log. Sem código, só a descrição **inteira** conta. Nota com `chSubstda` marca a antiga como `substituida` mesmo antes do evento. Prioridade: cancelada > substituida > demais; reprocessar nunca rebaixa. Esse status é distinto de fila/conferência. | `services/nfse_status_service.py::classificar_xml`, `legacy_ingestion_service::_prever_status_por_chave/_status_final_nota/_aplicar_substituicao/_registrar_evento_xml` | Não usar `status_fila_manual` para alterar status fiscal. Testes com XML reais mascarados em `tests/fixtures/nfse_reais` (`tests/test_classificacao_status_nfse.py`). Corrigido em 2026-09-25 (branch `ajustes/f1-status-fiscal`). |
| REG-015 | Direção emitida/recebida é classificada comparando CNPJ do certificado/empresa com prestador e tomador. | `notas_service::classificar_direcao_nota` | Falta de CNPJ produz direção desconhecida/heurística. |
| REG-016 | Status de fila manual tem precedência; depois cancelada/substituída; alertas/divergências levam a `divergente`; sem alertas, `correta`. | `operational_fields_service::calcular_status_fila` | Mudança em prioridade afeta dashboard, conferência e relatórios. |
| REG-017 | Prioridade manual vence a calculada; divergência com campos ausentes é `alta`, outra divergência/alerta `media`, restante `baixa`. | `calcular_prioridade_fila` | SLA usa prioridade final. |
| REG-018 | SLA: alta alerta 24h/perigo 48h; média 36/72h; baixa 72/120h; sem data = “Sem prazo”. | `SLA_THRESHOLDS`, `calcular_sla_operacional` | Timezone ingênuo é assumido UTC. |
| REG-019 | Simples Nacional é preferencialmente derivado do XML; códigos 1/2/3 viram Não optante/MEI/Optante S.N. | `operational_fields_service` | API externa não deve sobrescrever fonte XML sem regra explícita. |
| REG-020 | Campos `observacao_interna` e `alertas_fiscais` são somente leitura no payload de conferência. | `schemas.notas.NotaConferenciaUpdate` | API direta não pode forjar alertas fiscais. Os valores calculados para a tela usam `definir_valor_exibicao` (set_committed_value) e nunca são gravados pela conferência. |
| REG-021 | Status de conferência aceito é `pendente`, `ok`, `corrigir`, `observacao`; valores são normalizados para minúsculo. | mesmo schema | Outros valores retornam 422. |
| REG-022 | Nota já com `responsavel` gera 409 ao gravar sem `retificar=true`, tanto em `PATCH /notas/{id}/conferencia` quanto no contrato antigo `PUT /nfse/{id}` (que antes contornava a trava). Autor, `conferencia_por`, `operator_*` e a data vêm do usuário logado; `responsavel`/`atualizado_por`/`atualizado_em` do corpo e os cabeçalhos `X-Responsavel`/`X-Usuario-Nome` são ignorados. Cada gravação com mudança entra em `notas_conferencia_historico` (quem, quando, `analise`/`retificacao`, campo de→para); `GET /notas/{id}/historico` lista. Prioridade e status manual da fila só aceitam a lista fixa (com sinônimos); textos têm limite de tamanho. | `notas_service.py::salvar_conferencia/atualizar_conferencia`, `schemas/notas.py::NotaConferenciaUpdate`, `routers/notas.py`, `routers/nfse_compat.py` | Histórico sobrevive ao arquivamento (nota_id nulo) e à exclusão do usuário (usuario_id nulo). | REG-023 | Filtros possuem aliases (`status`→`status_documento`, datas, CNPJs, conferência e SLA) e `sort` limitado a `recentes`/`emissao`. | `schemas.NotasDownloadFiltros` | Alterar nomes exige compatibilidade no GET e POST. |
| REG-024 | Download lote sanitiza IDs positivos e únicos, seleciona XML/PDF, deduplica nomes e limita número de notas. | `schemas.NotasDownloadLoteRequest`, `notas_download_service` | Arquivos ausentes são tratados como erro/skip conforme serviço. |
