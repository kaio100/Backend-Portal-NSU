# Regras de negócio identificadas

As regras abaixo foram extraídas do código do snapshot `f50da548` e não são proposta de correção.

| ID | Regra | Implementação (trecho aproximado) | Consequência |
|---|---|---|---|
| REG-001 | Toda entidade operacional é limitada ao `grupo` do usuário; ausência de correspondência retorna 403/404. | `api/deps.py::require_*_grupo` | Não remover filtros tenant ao criar endpoints novos. |
| REG-002 | Usuário precisa estar ativo; papel `admin`, `operador` ou `leitura` define mutações. | `backend/app/core/security.py`, `backend/app/api/deps.py` | JWT válido de usuário desativado não autoriza. |
| REG-003 | Login é limitado por IP+email em janela de 5 minutos (8 tentativas). | `backend/app/core/rate_limit.py`, `backend/app/api/routers/auth.py` | Limite é por processo, não distribuído. |
| REG-004 | Empresa usa CNPJ normalizado com 14 dígitos e é única no banco. | `empresas_service.py`, `models.Empresa` | CNPJ inválido/duplicado falha antes do commit. |
| REG-005 | Consulta elegível requer certificado ativo, empresa ativa/grupo compatível, `storage_key` não pendente, validade e senha salva. | `consultas_service.py::list_certificados_elegiveis` | Certificado sem segredo não entra no scheduler. |
| REG-006 | Não é criado novo processo para certificado com consulta ativa, salvo opção explícita de força. | `consultas_service.py::has_active_consulta_for_certificado` | Evita duplicidade lógica, mas corrida entre sessões ainda é possível. |
| REG-007 | `MonitoramentoConfig.grupo` é único; scheduler enfileira apenas grupos automáticos ativos e no horário. | `consultas_service.py`, `worker/scheduler.py` | Configuração de um grupo não afeta outro. |
| REG-008 | Cursor NSU é monotônico por `(empresa_id, certificado_id)`; lookback normal/deep depende da janela e opção. | `nsu_control_service.py` | Reprocessamento deve ser idempotente. |
| REG-009 | `Processo` passa por `pendente → executando → finalizado/erro/cancelado`; `Job` tem attempts e lock. | `processos_service.py`, `worker/jobs.py` | Cancelar `running` marca estado, mas não interrompe cliente legado. |
| REG-010 | Em `WORKER_DRY_RUN=true`, o job simulado atualiza estados sem chamar ADN. | `worker/jobs.py::processar_job_simulado` | Ambiente local não valida integração real. |
| REG-011 | Lock de processamento é único por empresa/certificado e tem expiração. | `locks_service.py`, `models.LockProcessamento` | Worker morto depende de expiração/recovery. |
| REG-012 | Chave `(empresa_id, nota.chave)` é a identidade idempotente da nota. | `models.Nota`, `legacy_ingestion_service::upsert_nota_by_chave` | Mesma NFS-e em empresas distintas é permitida. |
| REG-013 | Namespace XML é ignorado para localizar tags; datas/decimais recebem normalização tolerante. | `legacy_ingestion_service.py`, `nfse_xml_parser.py` | XML malformado/sem chave é rejeitado ou enviado a erro de ingestão. |
| REG-014 | `cStat`, cancelamento e substituição determinam `status_documento`; esse status é distinto de fila/conferência. | `_status_from_xml`, `Nota` | Não usar `status_fila_manual` para alterar status fiscal. |
| REG-015 | Direção emitida/recebida é classificada comparando CNPJ do certificado/empresa com prestador e tomador. | `notas_service::classificar_direcao_nota` | Falta de CNPJ produz direção desconhecida/heurística. |
| REG-016 | Status de fila manual tem precedência; depois cancelada/substituída; alertas/divergências levam a `divergente`; sem alertas, `correta`. | `operational_fields_service::calcular_status_fila` | Mudança em prioridade afeta dashboard, conferência e relatórios. |
| REG-017 | Prioridade manual vence a calculada; divergência com campos ausentes é `alta`, outra divergência/alerta `media`, restante `baixa`. | `calcular_prioridade_fila` | SLA usa prioridade final. |
| REG-018 | SLA: alta alerta 24h/perigo 48h; média 36/72h; baixa 72/120h; sem data = “Sem prazo”. | `SLA_THRESHOLDS`, `calcular_sla_operacional` | Timezone ingênuo é assumido UTC. |
| REG-019 | Simples Nacional é preferencialmente derivado do XML; códigos 1/2/3 viram Não optante/MEI/Optante S.N. | `operational_fields_service` | API externa não deve sobrescrever fonte XML sem regra explícita. |
| REG-020 | Campos `observacao_interna` e `alertas_fiscais` são somente leitura no payload de conferência. | `schemas.notas.NotaConferenciaUpdate` | API direta não pode forjar alertas fiscais. |
| REG-021 | Status de conferência aceito é `pendente`, `ok`, `corrigir`, `observacao`; valores são normalizados para minúsculo. | mesmo schema | Outros valores retornam 422. |
| REG-022 | Nota já com `responsavel` gera 409 ao editar sem `retificar=true`; em retificação o usuário autenticado prevalece como responsável/autor. | `routers/notas.py::patch_conferencia_nota` | Retificação não cria versão histórica, apenas sobrescreve campos. |
| REG-023 | Filtros possuem aliases (`status`→`status_documento`, datas, CNPJs, conferência e SLA) e `sort` limitado a `recentes`/`emissao`. | `schemas.NotasDownloadFiltros` | Alterar nomes exige compatibilidade no GET e POST. |
| REG-024 | Download lote sanitiza IDs positivos e únicos, seleciona XML/PDF, deduplica nomes e limita número de notas. | `schemas.NotasDownloadLoteRequest`, `notas_download_service` | Arquivos ausentes são tratados como erro/skip conforme serviço. |
| REG-025 | Arquivo PDF preferido é oficial quando solicitado; caso contrário usa espelho; XML/PDF são indexados separadamente. | `notas_download_service`, `storage_naming_service` | Nota pode aparecer sem arquivo físico correspondente. |
| REG-026 | Retenções usam Decimal e arredondamento `ROUND_HALF_UP` em centavos; IRRF/PCC/INSS/ISS são comparados com tolerância de 0,01. | `retencoes_calculo_service.py` | Float novo em regras fiscais pode gerar divergência. |
| REG-027 | Regras LC116 vêm de `RETENCOES_REGRAS.xlsx` (Planilha2), com flags SIM/NAO/DEPENDE e exceção IRRF subitem 7.04 a 1%. | `retencoes_regras_service.py` | Alterar planilha muda cálculo sem alterar Python. |
| REG-028 | Storage aceita backend local/R2, normaliza separadores e rejeita `..`, caminhos absolutos e chaves fora da raiz. | `storage_service.py` | Chaves devem ser construídas pelo naming service. |
| REG-029 | Certificados são armazenados como bytes no storage; senha é referência para valor cifrado em `Secret`, nunca coluna plaintext. | certificados/secrets services | Perder `SECRETS_KEY` impede decifrar senhas. |
| REG-030 | DANFSe valida tamanho de XML e usa subprocesso PHP oficial; não há fallback Python. | `danfse_service.py`, `backend/danfse` | PHP/Composer é dependência de produção. |
| REG-031 | Arquivamento grava manifesto/backup antes de remover notas antigas; é operação administrativa destrutiva. | `notas_archive_service.py`, `/admin/arquivamento` | Deve ser executado com backup e reconciliação. |
| REG-032 | CNPJ externo é cacheado por `(cnpj, fonte)` com data de expiração/status; provider Invertexto pode estar desabilitado. | `cnpj_cache_service.py`, `portal_support_service.py` | Relatório pode mostrar “não consultado” sem ser erro de nota. |
| REG-033 | Para escolher o subitem fiscal, o primeiro candidato de código é usado quando tem regra na `Planilha2`; se não tem (ex.: `990101`→`99.01`), o parser tenta `cTribMun`, `itemListaServico` e demais candidatos antes de emitir “regra não encontrada”. | `retencoes_regras_service.py::resolver_subitem_lc116`, `legacy_ingestion_service.py::extrair_codigo_servico_xml` | Evita falso negativo quando o XML carrega código genérico antes do enquadramento LC116 válido; se nenhum candidato tiver regra, mantém o primeiro para diagnóstico. |
| REG-034 | A planilha é escolhida por `RETENCOES_REGRAS_PATH` ou, na ausência, pela cópia mais recentemente modificada entre `data/` e a raiz; cache é refeito quando tamanho/mtime mudam. | `retencoes_regras_service.py::_selecionar_planilha`, `_carregar_regras_cacheado` | Edições não exigem restart e a cópia errada não fica silenciosamente congelada. |
| REG-035 | `cTribMun`/códigos municipais simples de 3 dígitos não são usados como subitem LC116; só códigos nacionais ou municipais já formatados/com 4+ dígitos podem servir de candidato. | `retencoes_regras_service.py::normalizar_candidato_subitem`, `legacy_ingestion_service.py::extrair_codigo_servico_xml` | Evita colisões como `501`→`5.01`; o `cTribNac` original continua separado de um candidato municipal usado como fallback. |
| REG-036 | Notas com `status_documento` cancelada/substituída (qualquer caixa/espaços, também no masculino) nunca entram no ZIP em lote (por filtros ou por `nota_ids`, POST e GET) nem na planilha de conferência; a listagem do portal continua exibindo-as. O filtro é SQL, antes do limite, e mantém notas com status `NULL`. | `notas_repo.py::_somente_exportaveis` (`somente_exportaveis=True`), `notas_download_service._buscar_notas`, `portal_support_service._buscar_notas_relatorio` | Filtrar explicitamente por status cancelada numa exportação resulta em ZIP 404 "Nenhuma nota encontrada" / planilha vazia.
